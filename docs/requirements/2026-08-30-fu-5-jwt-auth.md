# FU-5 真实 JWT 认证替换 dev auth stub（仅登录）

**Date:** 2026-08-30
**Status:** approved
**Complexity:** complex

## Goal

用真实 JWT 认证替换 dev auth stub：`POST /api/auth/login` 签发 token，`authMiddleware` 校验 `Authorization: Bearer`，chat 说话人首次与真实登录者绑定；前端新增 `/login` 页 + 路由守卫 + 401 自动跳转；**stub 彻底移除，不留双路径**。本轮仅登录（用户拍板）：账号来源为种子用户 + 固定开发密码；自助注册/建号拆后续 FU。

## Background

- 路线图（[2026-08-21-phase2-agent-recommend-borrow.md](./2026-08-21-phase2-agent-recommend-borrow.md)）：FU-5 =「真实 JWT 替换 dev auth stub」，定位是"上生产前必须完成"；2026-08-19 决策明确 dev stub 是过渡方案。
- 用户已实际感知痛点：「点进去就是 admin 身份」——三个 admin API client 写死 `X-Dev-Role: admin`，chatApi 写死 user。
- 缺口盘点：`User` 模型无密码字段；api 无 `jsonwebtoken`/bcrypt 依赖；无 `/api/auth` 路由；无登录页/守卫；约 30+ 处 api 测试用 stub 请求头；`JWT_SECRET` 已在 `.env`/`.env.example` 备好但启动不校验。
- AGENTS §14：bcrypt 或 Argon2 哈希密码；启动时校验必需环境变量；生产错误不暴露堆栈。
- Phase 2 的 FU-1 文档曾把「创建 User」标注为 FU-5 范围——用户本轮拍板**仅登录**：注册/建号拆出（挂路线图，实施前走 grill-me）。
- 用户拍板：仅登录；账号来源 = 种子用户 + 固定开发密码。

## Requirements

- **REQ-1** db：`User` 增加 `passwordHash String`，迁移 `add_user_password_hash`；seed 为两个种子用户写入 bcrypt 哈希（开发固定密码：`user@fairy.local` → `user123456`，`admin@fairy.local` → `admin123456`，seed 注释标注 demo-only，生产必须改密）。
- **REQ-2** 依赖与安全：api 增 `jsonwebtoken` + `bcryptjs`（纯 JS，Windows 免原生编译）；`JWT_SECRET` 启动时必填校验（`index.ts`，缺失即退出并提示）；token payload `{ userId, role }`、HS256、12h 过期。
- **REQ-3** api auth 端点：`POST /api/auth/login`（email+password，Zod 校验；成功 `{ code, data: { token, user: { id, email, role } } }`；凭证错误统一 401 `UNAUTHORIZED` 不区分"用户不存在/密码错"）；`GET /api/auth/me`（Bearer 校验，返回当前用户摘要）。公共端点（免认证）仅 `/health`、`/api/auth/login`。
- **REQ-4** `authMiddleware` 重写：解析 `Authorization: Bearer <jwt>` → 验签 + 过期校验 → 注入 `res.locals.userId/role`；缺失/无效/过期 → 401 `UNAUTHORIZED`；`X-Dev-Role` 与 `Bearer dev-*` 路径**删除**；`requireRole` 逻辑不变。
- **REQ-5** shared：`authSchemas`（loginSchema、authUserSchema）+ 类型；错误码沿用 `UNAUTHORIZED`，无新增。
- **REQ-6** web：`authStore`（zustand + localStorage 持久化 token/user；`login()/logout()/restore()`）；`authApi.ts`（login/me）；4 个 API client 统一改造为从 authStore 注入 `Authorization`，收到 401 清 store 跳 `/login`；`/login` 页（邮箱+密码，错误页内提示，i18n）；路由守卫（`/chat` 需登录，`/admin/*` 需 admin，未授权跳 `/login`）；导航按角色渲染（admin 链接仅 admin 可见）+ 登录/退出按钮。
- **REQ-7** api 测试迁移：测试助手 `authHeader(role)` 用测试密钥签真实 JWT；全部 stub 请求头替换；新增 auth 路由测试（登录成功/密码错 401/me）。web 测试：mock authStore/authApi，登录页与守卫测试。
- **REQ-8** 文档：`API_CONTRACT.md`（认证节改 JWT、删各端点"开发环境认证"段、新增 §3.0 认证端点）；`ARCHITECTURE.md`（认证层与数据流）；`PROJECT_STATUS.md` 归档阶段更新；`.env.example` 的 `JWT_SECRET` 注明必填。

## Acceptance Criteria

- **AC-1**（自动化）`POST /api/auth/login` 正确凭证 → 200 拿到可用 token；错误密码/不存在邮箱 → 401 `UNAUTHORIZED`（响应一致，不区分原因）。
- **AC-2**（自动化）`X-Dev-Role` 头与 `Bearer dev-*` 全部失效 → 401（stub 移除断言）。
- **AC-3**（自动化）user token 访问 admin 端点 → 403 `FORBIDDEN`；无 token → 401；chat 以登录者 userId 作为说话人（借阅后 rentals 归属正确）。
- **AC-4**（自动化）过期/伪造 token → 401；`JWT_SECRET` 缺失时 API 启动即失败。
- **AC-5**（自动化）web：登录页成功进入 `/chat`；未登录访问 `/admin/movies` 跳转 `/login`；user 角色看不到 admin 导航；401 触发自动登出跳转。
- **AC-6**（自动化）迁移可应用（种子密码可登录）；全包测试 + typecheck 全绿。
- **AC-7**（联调）真机：登录 → 聊天借还（身份为登录者）→ admin 页管理 → 退出。

## In Scope

- 密码字段 + 迁移 + seed 密码；`/api/auth/login|me`；authMiddleware 重写（stub 删除）
- web：authStore、authApi、`/login`、守卫、4 个 client 改造、导航角色化
- api 测试迁移到真实 JWT + auth 路由测试；文档同步

## Out of Scope

- 自助注册 / admin 建号（拆后续 FU，实施前 grill-me）
- refresh token / 记住我 / 密码修改与找回；第三方登录
- 登出服务端 token 吊销（客户端清 store 即可）；rate limit（§14 后续硬化项，单独挂风险）
- 种子用户资料变更；多租户

## Key Decisions

| Decision | Choice | Rationale | Trade-off |
|---|---|---|---|
| 账号来源 | 仅登录，种子固定开发密码（用户拍板） | 最小切片；注册/建号拆出 | 新用户无法自助进入（演示够用） |
| stub 去留 | 彻底删除，不留双路径 | 双认证路径长期共存是负债；测试助手使迁移机械化 | 30+ 处测试改动（可脚本化） |
| 令牌形态 | 单 access token，HS256，12h | 无 refresh 的复杂度；演示与内网够用 | 过期需重登（无静默续期） |
| 密码哈希 | bcryptjs | §14 允许 bcrypt 系；纯 JS 免 Windows 原生编译坑 | argon2 更现代但构建成本高 |
| 凭证错误响应 | 统一 401 不区分原因 | 防用户枚举 | 用户体验略差（提示不精确） |
| 前端令牌存储 | localStorage + zustand persist | 简单；XSS 面由 React 默认转义 + 无 innerHTML 缓解 | httpOnly cookie 更防 XSS 但需 CSRF 处理（更大改造） |
| chat 说话人 | 登录者 userId | 身份真实化的核心收益 | 铃的画像绑定 user@fairy.local，演示需用该账号登录 |

## Technical Notes

- 迁移/seed 顺序：先 `add_user_password_hash` 迁移，再跑 seed 写哈希（`bcryptjs.hashSync`，cost 10）。
- 测试助手：`tests/helpers/auth.ts` 导出 `authHeader(role)` —— `process.env.JWT_SECRET` 在各测试文件 `beforeAll` 设为固定测试值；30+ 处 `.set("X-Dev-Role", x)` 用脚本批量替换为 `.set("Authorization", authHeader(x))`。
- web client 改造：`request()` 包装层统一注入 `Authorization: Bearer ${authStore.token}`；401 拦截在包装层做（清 store + `window.location` 跳转），业务层无感。
- `GET /api/auth/me` 供前端刷新页面后恢复会话（token 有效即还原 user）。
- helmet 已启用；生产不回显堆栈（现有错误中间件已满足）。
- 行为流水/画像等既有功能的 userId 语义不变——只是来源从 stub 常量变为 JWT payload。

## Risks & Open Questions

- 固定开发密码随仓库提交（seed 内明文常量 + 文档）：demo 库可接受；**上线前必须改密或改注册流程**（挂 risk）。
- localStorage 存 token 的 XSS 面：React 默认转义 + 无 dangerouslySetInnerHTML，当前面可接受；httpOnly cookie 方案挂 future。
- 无 rate limit：登录接口可被暴力尝试——demo 可接受，挂 future（FU 外单独项）。
