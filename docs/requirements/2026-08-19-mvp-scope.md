# Fairy MVP Phase 1 — 影片库 CRUD

**Date:** 2026-08-19
**Status:** implemented（已交付并归档；真机验收与归档记录见 PROJECT_STATUS.md Completed Modules）
**Complexity:** complex

## Goal

交付 Fairy 第一个可运行功能：影片目录的完整数据层（PostgreSQL + REST API）与单页管理端，为 Phase 2 的 Agent 推荐、借阅和搜索提供真实数据基础。不依赖 AI API 密钥即可端到端验证。

## Background

项目处于 Scaffolding 尾声（`PROJECT_STATUS.md`）。Monorepo 骨架、`Fairy/` 占位代码与脊柱文档已就位；可运行业务代码仅 `/health` 端点，Prisma 仅有 `User` 模型。

原 `API_CONTRACT.md` v1 仅定义 `GET /movies/search`，与 `PROJECT_STATUS.md` 规划的完整 CRUD 冲突。经 grill-me 确认：**以完整 REST CRUD + 管理端为 MVP Phase 1 权威范围**，实施时同步更新 `API_CONTRACT.md`。

技术约束来自 `ARCHITECTURE.md` 与 `AGENTS.md`：统一响应 `{ code, data, msg }`、Zod 校验在 `packages/shared`、mood/scene 严格枚举、写操作需鉴权。

## Requirements

- **REQ-1** 定义 `Movie` Prisma 模型，含 `title`、`director`、`year`、`mood[]`、`scene[]`、`genres[]`、`quote`、`stock`、`totalStock`、`coverUrl`、`description`、时间戳。
- **REQ-2** mood/scene 使用 Prisma 枚举，初始值见 Key Decisions；每部影片 1–3 个 mood、1–3 个 scene。
- **REQ-3** 提供 Prisma 迁移与 seed 脚本（至少 5 部示例影片）。
- **REQ-4** 在 `packages/shared` 定义 Movie Zod schema 与 Mood/Scene 枚举类型，前后端共用。
- **REQ-5** 实现 REST 端点：`GET /api/movies`（分页列表）、`GET /api/movies/:id`、`GET /api/movies/search`（mood/scene/keyword 过滤）、`POST /api/movies`、`PATCH /api/movies/:id`、`DELETE /api/movies/:id`。
- **REQ-6** 所有端点返回 `{ code, data, msg }`；列表响应 `data: { items, pagination }`。
- **REQ-7** 开发期认证 stub：`X-Dev-Role: admin | user` 或 `Authorization: Bearer dev-<role>`；写操作仅 admin，读操作 user + admin。
- **REQ-8** 单页管理端 `/admin/movies`：列表（分页 + mood/scene 筛选）、新建/编辑表单（模态或抽屉）、删除确认；文案走 `zh-CN.json` i18n。
- **REQ-9** 后端与前端单元测试覆盖核心 CRUD 与校验逻辑。
- **REQ-10** 完成后更新 `API_CONTRACT.md`、`PROJECT_STATUS.md`。

## Acceptance Criteria

- **AC-1** `pnpm --filter=@fairy/database migrate:dev` 成功创建 `Movie` 表与 mood/scene 枚举。
- **AC-2** seed 后 `GET /api/movies` 返回 ≥5 条影片，含分页元数据。
- **AC-3** `GET /api/movies/search?mood=治愈&scene=雨天` 仅返回匹配影片；未知 mood/scene 值被忽略。
- **AC-4** 无 admin 角色时 `POST /api/movies` 返回 403，`code: FORBIDDEN`。
- **AC-5** admin 角色可创建影片；`PATCH` 更新 stock 后 `GET /api/movies/:id` 反映新值；`DELETE` 后影片不可再获取（404）。
- **AC-6** 提交 mood/scene 超过 3 个或为空时，API 返回 400 校验错误。
- **AC-7** 管理端页面可完成列表查看、筛选、新建、编辑、删除全流程（dev-admin 角色）。
- **AC-8** `pnpm --filter=@fairy/api test` 与 `pnpm --filter=@fairy/web test` 通过。

## In Scope

- Movie REST CRUD + search 端点

- 协同过滤推荐算法
- Docker 部署、生产环境配置
- Trellis bootstrap spec 填充（并行任务，不阻塞本 MVP）

## Key Decisions

| Decision | Choice | Rationale | Trade-off |
|---|---|---|---|
| MVP Phase 1 | Movie CRUD + 管理端 | 数据层是 Agent 的前置依赖；不依赖 AI key | Agent/借阅延后 Phase 2 |
| Movie API | 完整 REST CRUD + search | 对齐 `PROJECT_STATUS.md` | 需重写 `API_CONTRACT.md` 影片章节 |
| mood 枚举 | `治愈` `热血` `悬疑` `致郁` `轻松` `浪漫` | 覆盖契约示例与推荐场景 | 扩展需迁移 |
| scene 枚举 | `雨天` `失眠夜` `周末午后` `独自在家` `约会夜` `通勤路上` | 同上 | 同上 |
| 标签 cardinality | 每片 1–3 mood、1–3 scene | 便于过滤，防泛滥 | 表单需校验 |
| 认证 MVP | Dev stub 角色头 | 无 JWT 密钥即可联调 | Phase 2 换 JWT；`.env.example` 标注 dev-only |
| 写/读授权 | 写=admin；读=user+admin | 门店管理模型 | 无匿名公开读 |
| 管理端 UI | 单页 `/admin/movies`，模态/抽屉表单 | 端到端验证 CRUD，交付快 | 无独立详情页路由 |

## Technical Notes

**数据层：** `Movie` 模型放在 `packages/database/prisma/schema.prisma`；mood/scene 用 Prisma `enum`，PostgreSQL 原生枚举或 Prisma enum array（按团队惯例选一种，OpenSpec 阶段定）。

**API 层：** 路由挂到 `apps/api/src/index.ts`；controller/service 分层遵循 `ARCHITECTURE.md` §3.2；`movieService.ts` 承载 Prisma 查询，事务留给 Phase 2 借阅。

**共享层：** `packages/shared/src/schemas/movieSchemas.ts` + `types/movieTypes.ts` 导出 Mood/Scene 枚举与 Movie DTO。

**前端：** `AdminDashboard` 下新增或挂载 `MoviesAdminPage`；React Router 注册 `/admin/movies`；Zustand 可选（列表状态可用本地 state）；请求带 `X-Dev-Role: admin`。

**文档对齐：** 将 `API_CONTRACT.md` §3 扩展为完整 CRUD 契约，保留并整合现有 `GET /movies/search` 定义；`PROJECT_STATUS.md` 在 OpenSpec archive 时标记完成。
