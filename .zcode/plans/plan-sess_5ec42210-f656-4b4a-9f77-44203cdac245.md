## FU-10 账号体系闭环：注册 / 登录限速 / refresh token

**流程**：OpenSpec 轨（跨 db+shared+api+web，改 API_CONTRACT 公共契约）。执行先产出 `docs/requirements/2026-09-01-fu-10-account-closure.md` + OpenSpec 提案 `openspec/changes/fu-10-account-closure/`（文档非产品代码），随后实现（本计划批准即视为需求/提案内容批准）。

### 1. 后端（apps/api + packages/database）

**注册 `POST /api/auth/register`**（免认证）
- shared 新增 `registerSchema`：`{ email: z.string().email(), password: min(6).max(72) }`；web 端 confirmPassword 仅前端校验
- 密码 bcrypt(cost 10)；role 恒 `"user"`（admin 只经 seed，不开放注册）；**只建 User，不自动建 Profile**（与 dev-admin 无画像现状一致）
- email 冲突 → 409 `EMAIL_ALREADY_EXISTS`（新错误码入 API_CONTRACT §4）；成功 201 返回 `{ token, user, refreshToken }`（与 login 同形状，注册即登录）

**登录限流**（新依赖 express-rate-limit v7）
- 限流器在 `createApp()` 内创建（测试隔离）：login `10 次/15 分钟/IP`；register `20 次/小时/IP`
- 429 统一 `{ code: "TOO_MANY_REQUESTS", data: null, msg }`（新错误码入契约）；生产反代需 `trust proxy`（文档标注）

**refresh token 旋转 + 吊销**
- Prisma 新模型 `RefreshToken`：`tokenHash @unique`（sha256 存随机 48B base64url token，不明文）、`userId` FK、`expiresAt`（30d）、`revokedAt`、`replacedByTokenId` 自关联、索引；迁移 `add_refresh_token_table`
- `POST /api/auth/login` 响应增加 `refreshToken`
- `POST /api/auth/refresh`（免认证，以 refresh token 自证）：校验 → 旋转（旧置 revokedAt + replacedByTokenId，发新对）→ 返回 `{ token, refreshToken, user }`；**复用检测**：已吊销/已替换 token 被再次使用 → 401 `INVALID_REFRESH_TOKEN` 并吊销该用户全部 refresh token（强制重登）
- `POST /api/auth/logout`：body `{ refreshToken }`，吊销当前 token；access token 自然过期
- `authMiddleware` / `me` 零改动；`JWT_SECRET` 不变，不新增环境变量
